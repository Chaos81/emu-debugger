ONLINE ARENA - PATCH v4 (boots the ROM from power-on)
======================================================

Contains the full "testing" folder (no ROMs). Replace your existing testing folder with it.

RUN
  From the folder that CONTAINS "testing":   python3 -m http.server 8000
  Open http://localhost:8000/testing/

PRE-GAME NOW HAS 3 STEPS
  1. Choose your system (Genesis or SNES) and pick your ROM file from your computer.
  2. Host online (3-letter room code) / join a friend's code / Local match.
  3. Start. The emulator boots the ROM from the very beginning; teams, players, home/away and
     rules are all chosen in the game's own menus.

REMOVED
  Single player / Two players, local Home / Away, "Choose your game", the Choose-the-matchup section,
  Match rules, Locked game conditions, the scoreboard and team logos above the screen, the
  result-share card, Save stats, and the author's "load a save" recovery panel.
  The site no longer reads the game's memory (no menu automation, no rule checks, no scores),
  so any ROM or ROM hack boots.

ONLINE
  The host chooses Player 1 (home) or Player 2 (away) with the side buttons; the guest gets the other port. Both players pick the same ROM file; as soon as they connect
  their ROMs are compared by CRC32 and Start is blocked, with both values shown, if they differ.
  SNES ROMs with and without a 512-byte copier header count as the same ROM.
  The guest follows the host's system choice.

SAVE STATES (Save state / Load state buttons, or [ and ])
  Work for both systems, local and online (only the host loads; the guest is resynced).
  Files are named after the ROM (nhl94.bin -> nhl94.state). They no longer check teams or settings.

END GAME returns to setup (online: for both players).

HEADER / FOOTER
  Header image is testing/assets/header.gif (replace the file to change it). The nav has a link to
  https://www.nhl94online.com. The intro block and the Enable-sound button are gone: sound starts
  automatically on your first click or key press (browsers require one gesture). Footer reads
  "NHL94Online.com Gaming".

CONSOLE PICTURES
  The idle game window shows testing/assets/console-genesis.svg or console-snes.svg. To use real
  photos, save them as testing/assets/console-genesis.jpg and console-snes.jpg; the page uses a
  .jpg automatically when it exists.

NOTE: All minified JavaScript (game/core/gpgx.mjs, snes.mjs, assets/arena-*.js, assets/service-*.js, game/ramvars.js, game/snes-boot.js) has been reformatted for readability (one statement per line, indented). Behavior is unchanged.

STABILITY: the diagnostics show "Stable (n ms)" or, when jitter is above 25 ms, an orange
"High jitter (n ms)" with a tooltip noting this is common on Wi-Fi and that wired plays smoother.

CHAT: during an online match a chat box appears under the Game Window. Messages (up to 200 characters)
go straight to the other player over the same peer connection (nothing is stored on a server). It is
hidden for local play and disappears on disconnect. Typing in it does not trigger game controls.
Chat shortcut: press Tab to jump into the chat box and Tab (or Esc) to return to the game. Tab keeps
its normal behavior when no online chat is open.

REPLAYS: Save replay (Play & Controls) downloads a .replay file for the current or last game: the ROM's
CRC32, and every controller input for both players by frame (run-length encoded), plus any save states
loaded during the game. Watch replay (setup screen, local mode, ROM loaded) boots that ROM from power-on and
feeds the recorded inputs, so the game plays out exactly as it did. Online, only confirmed inputs are
recorded, so rollbacks do not affect the file.

ONLINE PLAY REMOVED (emu-debugger)
  This copy is local-only. Removed: Host online / Join with room codes, PeerJS signaling and the
  bundled WebRTC adapter, rollback netcode, ROM CRC32 comparison between players, host player-side
  choice, chat and the player-name field, connection diagnostics (round trip, jitter, rollback,
  input delay, stability, transport) and the connection report, the network simulator, the online
  save-state transfer, and the tournament scheduler / community match queue. Setup is now 2 steps
  (system and ROM, then Start). Both controller ports are always live, so two players can play on
  one computer. Reset emulator works in every game. The ROM's CRC32 is shown once it loads.
  Old .replay and .state files still load.

NHL94ONLINE BRANDING REMOVED
  The header image and the NHL94Online link are replaced by a plain "EMU DEBUGGER" title; the
  footer reads "EMU DEBUGGER". Removed the NHL94Online coach-page export and the league stats ZIP
  (neither had a button on the page). Browser storage keys are now emu-debugger-volume and
  emu-debugger-ramwatch-<system>; the old nhl94online-* values are still read, so saved volume and
  RAM watch lists carry over.

GAME-SPECIFIC CODE AND WORDING REMOVED
  The site is now a plain Genesis / SNES emulator. Removed the hockey wording from the page and help,
  the EARLY PROTOTYPE badge, and the game-specific code behind it: team lists and pairings, match
  rules (mercy, tournament), the result-share card, in-game score reading, the stats capture and
  saved-game resume panel, the "choose your lines" phase, the NHL '95 and Sega CD entries (and the
  Sega CD disc cache), and game/boot.js, game/snes-boot.js and game/ramvars.js. SNES controller
  mapping labels are plain "SNES Y" / "SNES X".
  The emulator build fingerprint now covers only the core (wasm + mjs) and its version, so editing
  emu.js / snes.js no longer invalidates save states and replays. Saves and replays from earlier
  builds are still accepted. New save states start with "EMUS" and new replays use format
  "EMU-REPLAY"; older "NHLS" states and "NHL94-REPLAY" replays still load.

DEBUGGER
  The RAM viewer is now the Debugger window (ramviewer.js -> debugger.js; saved watch lists carry over).
  - Run control: Pause / Resume, Step frame, Step N frames (1-600) and the frame counter. In the debugger
    window F8 pauses / resumes, F10 steps one frame, Shift+F10 steps N. A Step frame button is also under
    Emulator control. Pausing no longer covers the picture; a small PAUSED badge shows instead.
  - Watch list: click a value to edit it (decimal or $hex, range-checked for its type); Freeze keeps the
    value fixed. CSV import accepts an optional third "type" column; Save CSV exports the list.
  - Memory view: 256-byte pages with ASCII, paging and Go to address; click a byte to edit (Tab moves on),
    right-click to freeze / unfreeze. Changed bytes are highlighted yellow, frozen bytes blue.
  - Frozen bytes are rewritten after every emulated frame (live play, steps and replay playback) and are
    cleared when the game ends. Any RAM change stops replay recording for that game, since replays store
    only inputs; Save replay keeps the part recorded before the change.

FIX: Pause / Resume in the debugger sometimes needed several clicks
  When the debugger window covered the game window, Chrome treated the game page as hidden: it stopped
  the game's frame loop and the auto-pause-when-hidden rule paused the game, so Resume appeared to do
  nothing. The debugger window now drives the game loop from its own animation frames whenever the game
  page gets none, and the game no longer auto-pauses on a hidden tab while the debugger is open.

DEBUGGER: REGISTERS
  New Registers pane in the debugger window, as of the end of the last frame (between instructions):
  - Genesis 68000: D0-D7, A0-A7, PC, SR, USP, SSP, the T S X N Z V C flags and the interrupt mask.
  - SNES 65816: A, X, Y, S, D, DB, PB, PC, P, the N V M X D I Z C flags, E, and the A / X,Y widths.
  Changed registers are highlighted like changed RAM. Clicking an address register that points into work
  RAM (68000 A0-A7 / USP / SSP, 65816 S, D, X, Y in bank 0) moves the memory view there.
  The cores do not export registers, so game/emu.js and game/snes.js read the CPU structs straight from
  WebAssembly memory (m68k in Genesis Plus GX; Registers + ICPU in snes9x2010). Their positions were found
  and checked with test ROMs for these exact core builds, so the pane only appears when the core
  fingerprint matches (PLATFORMS[*].registerBuilds). SNES N/Z/C/V are taken from ICPU because the packed P
  byte is not updated at the end of every frame.
  Also fixed: in a narrow debugger window (under 820 px) the panes now stack and the window scrolls,
  instead of squeezing the watch list out of view.

DEBUGGER: HEX CALCULATOR
  A Calculator button in the debugger toolbar opens calculator.html in its own window (clicking again
  brings it to the front without resetting it). It also works on its own.
  - Sizes: Byte (8-bit), Word (16-bit), Dword (32-bit). Switching size keeps the low bits.
  - Input in HEX or DEC; the value is always shown in hex, unsigned decimal, signed decimal and binary,
    plus a bit grid (click a bit to flip it). Click any value to copy it; paste $1F, 0x1F, 1Fh,
    %1010, 0b1010 or -12.
  - + − × ÷ MOD (÷ / MOD unsigned, or signed with "Signed ÷ / MOD", which truncates like DIVS);
    AND OR XOR NOT NEG; LSL LSR ASL ASR ROL ROR, where the next value is the count.
  - N Z V C flags after each operation, set as the 68000 would (C = carry / borrow or last bit out;
    V = signed overflow, or for ASL the sign bit changing during the shift).
  - Operators chain left to right; "=" again repeats the last step; history of the last 12 steps.
  - Keyboard: 0-9 A-F, + - * / %, & | ^ ~, < > (LSL / LSR), N (NEG), Enter, Backspace, Delete (CE),
    Esc (clear). Size, base and the signed setting are remembered.
  The maths is in calculator.js without any page code; every byte-size operation was checked against
  an independent bit-by-bit reference for all input pairs.
